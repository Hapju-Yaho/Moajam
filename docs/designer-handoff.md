# 모아잼(Moajam) 디자이너 전달용 서비스 기획서

작성일: 2026-09-29  
목적: 서비스의 전체 구조와 화면별 역할을 이해하고, 디자인 작업 범위를 협의하기 위한 문서.

현재 제품 요구사항과 작업 중인 화면 코드를 기준으로 정리했다. **현재 화면에 있는 기능**, **제품이 목표로 하는 확장 기능**, **디자인 작업을 위한 제안**을 구분한다. 화면에 기능이 있어도 실제 운영 환경과 모바일 기기에서 검증까지 완료되었다는 의미는 아니다.

## 1. 서비스 개요

### 한 문장 소개

**모아잼은 밴드와 합주팀이 곡을 고르고, 각자 연습하고, 함께 합주하는 과정을 곡 하나를 중심으로 관리하는 협업 서비스다.**

브랜드 문구: “각자의 소리를 모아, 우리의 음악으로.”

### 해결하려는 문제

- 연주할 곡에 대한 추천과 의견이 대화 속에 묻힌다.
- 악보, 참고 영상, 음원, 개인 녹음이 여러 곳에 흩어진다.
- 누가 어떤 파트를 맡았고 얼마나 준비했는지 한눈에 알기 어렵다.
- 합주 때 정한 편곡과 다음에 할 일을 다시 찾기 어렵다.
- 여러 밴드에 참여하면 일정과 준비할 곡을 따로 확인해야 한다.

모아잼은 **곡별 협업 공간**, **개인 연습 도구**, **합주 일정과 기록**을 연결해 이 문제를 해결한다.

### 주요 사용자

| 사용자 | 주로 하고 싶은 일 |
| --- | --- |
| 밴드 관리자 | 멤버 초대, 연주곡 확정, 파트 배정, 합주 일정 관리, 팀 준비 상황 확인 |
| 밴드 멤버 | 곡 추천, 의견 교환, 자료 확인, 개인 연습, 준비 상태 공유, 합주 참석 응답 |
| 여러 밴드에 참여하는 사용자 | 모든 밴드의 일정과 본인이 연습할 곡을 통합 조회 |

같은 사람도 밴드마다 역할과 담당 악기가 다를 수 있다.

### 서비스의 핵심 구조

1. **개인 공간**: 내가 속한 여러 밴드의 일정과 참여 곡을 모아보고 개인 연습을 하는 곳.
2. **밴드 공간**: 선택한 한 밴드의 추천곡, 채택곡, 합주, 멤버를 관리하는 곳.
3. **곡 상세**: 채택된 곡의 파트, 의견, 자료, 연습, 합주 기록을 모으는 핵심 작업 공간.

같은 노래를 서로 다른 밴드에서 연주해도 파트 배정, 자료, 준비 상태, 합주 기록은 밴드별로 구분한다. 개인 공간에서 보는 팀 일정과 곡은 해당 밴드의 정보를 모아 보여주는 것이며 별도 사본이 아니다.

## 2. 대표 사용 흐름

### 처음 시작할 때

카카오 로그인 → 개인 홈 → 밴드 만들기 또는 초대받은 밴드 참여 → 밴드 홈.

현재 임시 로그인은 개발·체험 환경을 위한 기능이다. 일반 사용자의 기본 시작 흐름은 카카오 로그인을 기준으로 한다. 별도의 이메일·비밀번호 가입 화면은 현재 범위에 없다.

### 새 곡을 함께 준비할 때

곡 추천 등록 → 멤버들의 좋아요·채택 추천·의견 → 관리자가 채택 → 곡 상세 생성 → 참여자와 파트 배정 → 편곡 기준과 자료 공유 → 각자 연습 → 내 준비 상태 갱신.

### 합주하고 다음 연습으로 이어갈 때

합주 일정 등록 → 참석 응답과 세트리스트 확인 → 합주 진행 → 녹음·메모·곡별 회고 기록 → 결정사항과 다음 할 일 정리 → 다음 개인 연습.

의견에서 결정된 내용을 곡의 할 일로 연결하는 기능이 있다. 곡별 할 일과 합주 세션별 할 일의 자동 동기화, 다음 합주로의 자동 이관은 확장 범위다.

## 3. 전체 화면 구조

```text
시작
└─ 로그인 / 밴드 만들기 / 초대 참여

개인 공간
├─ 개인 홈
├─ 합주 일정 — 화면 제목: 내 캘린더
├─ 참여 곡
└─ 연습실
   ├─ 내 악기 추출
   └─ 악보 편집

밴드 공간 — 현재 밴드 선택·전환
├─ 밴드 홈
├─ 곡 추천
│  └─ 추천곡 상세
├─ 채택곡
│  └─ 곡 상세
│     ├─ 메인
│     ├─ 개요
│     ├─ 의견
│     ├─ 자료
│     ├─ 연습
│     └─ 합주 기록
├─ 합주 — 일정 목록과 선택한 합주 상세
└─ 멤버

공통
├─ 알림
├─ 설정
└─ 도움말
```

웹은 사이드바에서 개인 메뉴와 밴드 메뉴를 구분한다. 모바일은 공간 선택과 해당 공간의 하단 메뉴를 사용한다. 밴드 화면에는 현재 밴드 이름이 드러나야 한다. 밴드가 없는 사용자에게는 만들기·참여하기를 안내한다.

| S02 밴드 시작·전환 | 참여 밴드 목록, 내 파트·역할, 현재 선택 밴드 | 밴드 선택, 이름 입력 후 생성, 초대 링크·코드로 참여 | 밴드 없음, 생성 중·실패, 유효하지 않거나 만료된 초대, 이미 참여한 밴드 |

| P02 합주 일정 / 내 캘린더 | 전체 밴드 일정과 개인 일정, 월간 달력, 선택한 날짜의 일정 | 월·날짜 선택, 개인·밴드 필터, 일정 등록, 개인 일정 수정·삭제, 팀 합주 상세 이동, 캘린더 파일 내보내기 | 선택 날짜에 일정 없음, 일정 겹침, 저장 실패, 팀 일정 관리 권한 없음 |
| P03 참여 곡 | 실제로 참여 파트가 배정된 활동곡, 밴드명, 내 파트, 내 준비 상태 | 곡·아티스트 검색, 밴드·준비 상태 필터, 준비 상태 변경, 연습·곡 상세 이동 | 참여 곡 없음, 검색 결과 없음, 파트 미배정 |
| P04 개인 연습실 | 밴드·곡 선택, 선택한 곡의 연습 트랙과 메모 | 음원 추가, 재생·녹음, 곡 전환, 곡 상세 이동, 개인 음악 도구 진입 | 곡 미선택, 트랙 없음, 녹음 권한 거부, 재생·파일 오류 |

**개인 홈의 핵심 질문**: “다음 일정이 언제이고, 지금 어떤 곡을 준비하면 되는가?”

개인 일정은 본인에게만 보인다. 팀 일정은 선택한 밴드의 멤버에게 공유되며 관리자 권한으로 등록·관리한다. 일정 등록에서는 공개 대상을 먼저 명확히 보여준다.

참여 곡의 준비 상태는 **준비 전 / 연습 중 / 준비 완료**다. 본인의 상태만 변경하며, 곡 상세와 팀의 준비도 집계에 반영된다. ‘이 곡에 미참여’와 ‘참여하지만 준비 전’은 다른 상태다.

### 4-2. 밴드 홈과 선곡

| ID / 화면 | 목적과 핵심 정보 | 주요 행동 | 함께 설계할 상태 |
| --- | --- | --- | --- |
| B01 밴드 홈 | 현재 밴드 소개, 다음 합주, 밴드 캘린더, 채택곡과 준비 현황, 추천 후보, 멤버 | 일정·연습·추천 상세 이동, 멤버 보기 | 새 밴드, 예정 합주 없음, 채택곡 없음 |
| B02 곡 추천 목록 | 곡 제목·아티스트, 영상 정보, 추천 이유, 좋아요·채택 추천, 보류·채택 여부 | 검색·정렬, 곡 추천 등록, 반응, 추천 상세 이동 | 추천 없음, 검색 결과 없음, 중복 링크, 영상 정보 조회 실패 |
| B03 추천곡 상세 | 추천 이유와 작성자, 참고 영상, 멤버 의견, 반응 수, 채택 여부 | 좋아요·채택 추천 토글, 의견·답글, 작성 내용 관리, 관리자 채택·보류·재논의 | 일반 멤버·관리자 차이, 이미 채택됨, 보류 사유, 삭제되거나 없는 곡 |
| B04 채택곡 목록 | 활동곡·보관곡 집계, 곡별 실제 참여자, 파트 준비도, 내 파트, 다음 합주 | 검색, 전체·연습 중·준비 완료·보관함 필터, 제목·준비도 정렬, 상세·연습 이동 | 첫 채택 전, 검색 결과 없음, 보관곡만 존재, 참여자 미배정 |

**좋아요와 채택 추천은 다른 행동**이다. 좋아요는 선호 표현, 채택 추천은 함께 연주할 곡으로 지지하는 의미다. 각각 취소할 수 있으며 반응이 많아도 자동으로 채택되지 않는다. 최종 채택·보류는 관리자가 수행한다.

곡 추천 등록은 영상 링크, 곡 제목, 아티스트, 추천 이유를 다룬다. 링크 정보 확인 중·성공·실패와 수동 정보 입력 상태를 함께 설계한다.

| C03 의견 | 편곡·톤·연주 방식에 대한 의견, 영상 첨부, 답글, 결정 여부 | 작성·수정·삭제, 답글·좋아요, 내용·답글·작성자 검색, 논의·결정·내 의견 필터, 결정된 의견을 할 일로 연결 | 의견 없음, 검색 결과 없음, 작성자·관리자 차이, 이미 할 일에 연결된 결정 |

| C05 연습 | 현재 곡의 연습 도구, 내 준비 상태, 밴드 기준 Key·BPM | 트랙 추가·재생·녹음·공개, 곡 자료 음원 가져오기, 개인 연습 BPM 변경, 구간 반복·메모 | 보관곡·미참여 곡의 개인 연습, 트랙 없음, 녹음 권한·저장 오류 |
| C06 합주 기록 | 이 곡을 세트리스트에 포함한 합주, 예정·완료·취소 구분, 완료된 합주의 곡별 회고 | 합주 상세 이동, 회고 작성·수정, 관리자가 예정 합주에 곡 연결 | 기록 없음, 예정 합주 없음, 이미 연결된 곡, 회고 미작성 |

**메인은 요약과 바로 할 행동**, **개요는 곡 정보·편곡·참여자 관리**가 중심이다. 두 화면이 같은 내용을 반복하는 느낌이 들지 않도록 역할을 구분한다. ‘메인 / 개요’ 명칭은 이 차이가 더 잘 드러나는 이름으로 개선할 수 있다.

팀 준비도는 실제 곡 참여자의 준비 완료 수를 기준으로 한다. 예를 들어 “4명 중 3명 준비 완료”를 숫자와 진행 막대로 함께 표현한다. 자동으로 연주 실력을 평가한 점수가 아니다.

| B05 합주 | 합주 일정 목록, 선택한 세션의 날짜·시간·장소·목표, 참석자와 응답, 세트리스트, 확인사항, 녹음·메모·할 일 | 관리자의 일정 생성·수정·취소·복원과 세트리스트 관리, 본인 참석 응답, 확인사항 체크, 녹음과 기록 추가, 할 일 담당자 지정 | 일정 없음, 예정·완료·취소, 참석 미응답, 세트리스트 없음, 녹음 없음, 잘못된 날짜·시간 |

합주 기록은 세션별로 구분한다. 다른 날짜의 녹음, 확인사항, 메모가 섞이지 않아야 한다. 참석자 지정과 멤버 본인의 참석 응답도 구분해서 보여준다.

| --- | --- | --- | --- |
| T01 내 악기 추출 | 업로드한 합주 녹음에서 선택한 악기 소리를 추출하는 도구 | 원본 업로드·미리듣기, 악기 선택, 작업 요청·상태 확인·취소·재시도, 원본·추출 악기·나머지 소리 비교, WAV 결과 보관 | 파일 미선택, 용량·형식 오류, 대기·처리·성공·실패·취소, 실행 환경 미연결 |

개인 악보는 기본적으로 개인 결과물이다. 편집 내용을 저장했다고 자동으로 팀의 공유 악보가 되지는 않는다. 현재 곡 자료에 공유하려면 내보내기 후 업로드가 필요하며, 자료에 바로 게시하는 흐름은 확장 항목이다.

## 5. 연습 화면에서 구분해야 할 기능

개인 연습실과 곡 상세의 연습 탭은 같은 연습 도구를 사용하지만 진입 맥락이 다르다. 개인 연습실은 연습할 밴드·곡 선택이 필요하고, 곡 상세에서는 현재 곡에 바로 집중한다.

| 기능 묶음 | 현재 웹 화면에 있는 기능 | 설계 시 유의점 |
| --- | --- | --- |
| 재생 | 여러 트랙의 동시 재생, 재생·정지·탐색, 트랙별 음량·음소거·솔로 | 전체 재생 조작과 개별 트랙 조작을 구분 |
| 반복·타이밍 | A–B 구간 반복, 트랙 시작 시점 조절 | 반복 중 여부와 시간 차이 조절 값을 명확히 표시 |
| 연습 보조 | 메트로놈, 카운트인, 시간 메모 | 곡 상세의 개인 연습 BPM은 메트로놈 설정이며 음원 속도 변경을 뜻하지 않음 |
| 녹음 | 마이크 녹음, 저장·다운로드 | 녹음 전 권한, 녹음 중, 중지, 저장 결과를 구분 |
| 자료 연결 | 곡 자료 음원을 연습 트랙으로 가져오기, 선택한 개인 트랙을 밴드에 공개 | 개인 보관과 밴드 공유를 명시적으로 구분 |

밴드의 기준 BPM과 개인의 연습 BPM은 별개다. 개인 연습 설정을 바꿔도 팀의 편곡 기준이 바뀌지 않는다.

모바일은 파일 추가, 개별 재생, 녹음, 메모 등으로 지원 범위에 차이가 있다. 웹의 멀티트랙 동시 재생과 정밀한 오디오 조작을 모바일에도 모두 제공한다고 전제하지 않는다.

## 6. 화면 외에 필요한 입력창과 보조 UI

아래는 현재 화면에서 확인한 주요 모달·선택창·인라인 패널이다. 각각을 별도 페이지 수로 중복 계산하지 않고, 연결된 화면의 하위 상태로 디자인한다.

| UI | 진입 위치 | 내용과 주요 행동 |
| --- | --- | --- |
| 공간·밴드 선택 | 공통 메뉴 | 개인 공간, 참여 밴드, 현재 선택, 내 파트·역할, 만들기·참여하기 |
| 밴드 만들기 | 밴드 선택기 | 밴드 이름, 생성·닫기, 생성 중·오류 |
| 밴드 참여 | 밴드 선택기·계정 설정 | 초대 코드·링크 입력, 수락, 성공·실패 |
| 곡 추천 등록 | 곡 추천 목록 | 영상 링크 확인, 제목·아티스트·추천 이유, 등록·취소 |
| 일정 등록·개인 일정 수정 | 개인·밴드 캘린더 | 개인·팀 구분, 밴드, 이름, 날짜, 시작·종료 시각, 장소, 여러 줄 메모 |
| 날짜·시간 선택 | 일정 입력 | 월별 달력, 오늘 선택, 오전·오후·시·분 휠, 총 소요 시간과 잘못된 시간 안내 |
| 합주 생성·편집 | 합주 화면 | 세션명, 일시, 장소, 목표, 참석 멤버 선택, 저장·취소 |

| 합주 할 일 담당자 | 합주 상세 | 할 일별 멤버 지정·미지정, 완료 |

| 리마인드 안내 | 멤버 화면 | 수신 대상 안내, 발송할 내용 편집, 발송, 결과 확인 |

날짜·시간 선택기는 일정 작성 중 사용하는 하위 UI다. 여러 겹의 모달이 겹치지 않게 구성하는 것이 좋다. 입력창은 기본 상태 외에 입력 중, 필수값 누락, 저장 중, 저장 실패, 완료 상태를 함께 고려한다.

## 7. 권한과 공개 범위

| 항목 | 관리자 | 일반 멤버 |
| --- | --- | --- |
| 곡 추천·반응·의견·자료 등록 | 가능 | 가능 |
| 곡 채택·보류, 곡 기본 정보·편곡 관리 | 가능 | 조회 중심 |
| 곡 참여자·파트 배정 | 가능 | 본인 배정 확인 |
| 본인 준비 상태·본인 참석 응답 | 변경 가능 | 변경 가능 |
| 팀 합주 일정·세트리스트 관리 | 가능 | 조회·본인 응답 |
| 공식 결정 표시, 멤버·초대 관리 | 가능 | 조회 중심 |
| 개인 일정·개인 녹음·개인 악보 | 본인 항목 관리 | 본인 항목 관리 |

세부 수정·삭제 권한은 대상에 따라 다르다. 의견·링크에는 작성자 또는 관리자 권한이 적용되는 동작이 있고, 파일의 공개 범위 변경·삭제는 소유자 기준이다. ‘관리자니까 모든 개인 파일을 볼 수 있다’는 식으로 표현하지 않는다.

다른 멤버가 남아 있는데 마지막 관리자가 탈퇴하려면 먼저 다른 멤버를 관리자로 지정해야 한다. 본인만 남은 밴드에서 탈퇴하면 밴드와 관련 데이터가 삭제되는 별도 확인 흐름이 있다.

## 8. 후속 확장으로 분리할 기능

아래는 제품 목표에 포함되어 있거나 기존 문서에서 제안했지만, 현재 기능과 동일한 완성도로 제공한다고 표현하면 안 되는 항목이다.

| 영역 | 후속 설계·개발 범위 |
| --- | --- |
| 연습 미디어 | 파형, 정교한 타임라인 댓글·마커, 업로드 음원의 4개 파트 분리와 연습 통합, 멤버 녹음 비교 흐름 |
| 악보 연동 | PDF·이미지 악보를 재생 화면에 표시, 시간과 페이지를 연결해 자동 넘김 |
| 개인 악기 추출 | 분리 강도·누음 억제 조절, 품질 피드백, 추가 내보내기 형식 |
| 악보 편집 | 고급 다성부 편집, 표준 조판, 페이지 단위 PDF, 영구 변경 이력, 밴드 자료에 직접 게시 |
| 협업 | 실시간 변경 반영과 충돌 해결 UI, 편곡·자료 버전 이력, 곡·합주 할 일의 양방향 연결 |
| 알림 | 변경에 따른 자동 알림, 합주 전 예약 알림, 이메일·모바일 푸시 |
| 운영 | 계정 삭제·이관, 문의 접수, 요금제와 사용량 정책 |

참고 영상은 곡을 듣고 편곡을 논의하기 위한 자료다. 영상 링크를 등록하면 자동으로 음원이 다운로드되거나 분리된다고 설계하지 않는다. PDF·이미지 악보를 올리면 편집 가능한 악보로 자동 변환되는 기능도 현재 범위에 없다.

## 9. 디자인 작업 순서 제안

아래는 작업량 협의를 위한 제안이며 확정된 계약·일정이 아니다.

1. **구조와 핵심 동선**: 개인·밴드 이동 구조 → 개인 홈 → 추천 등록·상세 → 채택곡 목록 → 곡 상세 메인·개요.
2. **협업 완성**: 의견·자료 → 합주 일정과 기록 → 멤버·초대 → 공통 입력창과 예외 상태.
3. **연습 경험**: 개인 연습실과 곡 상세 연습 → 녹음·공개 흐름 → 모바일 지원 범위에 맞춘 구성.
4. **보조 화면과 전문 도구**: 설정·도움말·알림 → 내 악기 추출·악보 편집.

초기 협의에서는 웹·모바일 중 어느 쪽을 먼저 완성할지, 전문 음악 도구를 첫 디자인 범위에 포함할지 결정하면 된다. 기존 시안은 서비스 이해용 참고 자료로 사용하고, 화면 구조나 배치를 그대로 복제할 필요는 없다.

권장 전달 결과물은 전체 화면 목록, 핵심 흐름 와이어프레임, 주요 화면 디자인, 공통 컴포넌트, 권한·빈 화면·로딩·오류 상태, 클릭 가능한 핵심 흐름이다.

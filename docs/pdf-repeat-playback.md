# PDF 마디 반복 분석과 재생

PDF 마디 구조 분석에서 도돌이표와 반복 횟수, 1·2번 반복 괄호를 함께 요청한다. 추가 분석 API 호출은 없다. 기존에 저장한 분석은 반복 정보가 없으므로 마디 설정에서 수동으로 추가하거나 마디를 다시 분석한 뒤 저장한다.

## 저장

각 마디에 선택적인 `repeat` 값을 저장한다.

```json
{
  "start": false,
  "end": { "target": 1, "times": 2 },
  "ending": { "passes": [1], "end": 8 }
}
```

- `start`: 이 마디 앞의 반복 시작 기호.
- `end`: 이 마디 뒤의 반복 끝 기호. `times`는 추가 반복 횟수가 아닌 총 연주 횟수(2~8).
- `ending`: 반복 괄호의 첫 마디에만 기록. 마지막 마디를 포함한 범위와 연주할 회차.
- 기호가 없으면 `null`. 이전 분석처럼 필드가 없어도 호환된다.
- 돌아갈 마디는 PDF 영역이 생략된 번호도 지정할 수 있다. 그 구간은 기존과 같이 대기 시간으로 처리한다.

기존 PersonalDocument의 PDF 마디 정보 JSON 안에 저장하므로 DB 테이블·컬럼 변경이나 마이그레이션 명령은 필요 없다. 메인 배포 시 서버와 웹 코드를 함께 갱신하면 된다.

## 재생

원본 마디와 규칙만 저장하고, 재생 시 실제 연주 순서로 펼친 목록을 계산한다. PDF 영역은 원본을 재사용한다. 목록에는 각 등장 위치의 누적 박자와 방문 회차를 계산한다. 안전을 위해 펼친 순서는 최대 65,536마디로 제한한다.

등록 음원은 펼친 누적 박자와 BPM, 곡 음원의 시작 위치로 재생 시간을 계산한다. 악보의 도돌이표를 통과할 때 음원을 되감지 않는다. 마디 클릭은 현재 누적 재생 위치에 가장 가까운 해당 마디의 등장 위치로 이동한다. 사용자가 직접 지정하는 구간 반복은 별도의 기능이며, 해당 구간을 되감고 설정된 카운트다운을 진행한다.

음원이 악보와 같은 순서와 고정 BPM으로 연주되었다는 전제다. 공연의 가변 템포나 다른 곡 구성의 자동 정렬은 지원하지 않는다. D.C., D.S., Fine, Coda는 이번 범위에 포함하지 않으며 인식 시 확인 경고를 요청한다.

## 확인

분석 화면 오른쪽에서 반복 시작·끝, 돌아갈 마디, 총 연주 횟수, 반복 괄호와 끝 마디를 수정한 뒤 저장한다. 크기는 PDF 테두리를 드래그해서 변경하고, 기존 화살표 패널은 줄 위치 이동에 사용한다. 잘못된 범위나 과도한 반복은 저장·재생 전에 안내한다.

유료 OpenAI 요청 없이 모의 요청·저장·복원 테스트와 반복 재생 순서 테스트로 검증한다. 실제 PDF의 인식 정확도는 사용자가 분석 결과를 확인해야 한다.

# PDF 악보 공통 인식 규칙

공통 요청은 `apps/server/src/score-pdf/recognition-request.ts`의
`commonRecognitionInstructions`에서 관리한다. 악기별 음정·주법 규칙과 분리했다.

- 마디선으로 마디를 세고, 줄·페이지 변경이나 여러 오선 때문에 중복 계산하지 않는다.
- 같은 연주의 오선·타브는 하나로, 독립적인 멜로디·반주는 별도 파트로 유지한다.
- 인쇄 마디 번호를 유지하고 생략된 번호는 순서대로 이어간다. 반복을 펼쳐 마디를 복제하지 않는다.
- 시간은 기존 변환기와 같은 **4분음표 단위 분수**를 사용한다. 온음표 `[4,1]`, 8분음표 `[1,2]`, 8분 셋잇단 `[1,3]`. 내부 계산은 4분음표당 48틱이다.
- 동시음·성부의 길이를 직렬 합산하지 않는다. 붙임줄과 이음줄, 꾸밈음을 구분한다.
- 박자·조표는 명시된 변경 전까지 이어받는다. 초기 박자 미인식은 임시 4/4와 경고, BPM·조표 미인식은 null로 반환하고 서버 기본 120·조표 없음을 적용한다.
- 악기명 우선, 없으면 표기 형태로 임시 악기를 추정하고 경고한다. 지원하지 않는 줄 수·튜닝은 경고하며 임의로 버리지 않는다.
- 확실한 쉼표와 미인식 영역을 구분한다. 읽지 못한 마디를 빈 이벤트로 반환하지 않는다.

## 현재 적용 범위와 한계

재분석(단일 페이지·마디 또는 선택 마디 일괄 요청)에만 서버가 확정된 마디 경계로 PDF를 실제 PNG 확대 이미지로 렌더링해 첨부한다. 모든 악기의 초기 구조 분석과 최초 음표 분석은 전체 PDF만 전달한다. 재분석은 전체 PDF를 다시 보내지 않고 선택 마디 이미지·확정 구조의 악기/박자 정보·`scoreContext`를 보낸다. 구조 단계에서 최대 6000자의 범례·튜닝·음자리표·지속 지시 문맥과 적용 시작 마디를 보존하며, 범례가 없으면 지어내지 않도록 한다. 기존 작업에 문맥이 없으면 불확실성을 표시한다. 각 확대 이미지 앞에 파트 ID·원본 페이지·마디 번호·원본 영역 좌표를 붙이며, 모두 한 번의 API 요청으로 보낸다. 이미지의 기호 위치는 원본 페이지 기준 0~1000 좌표로 환산해 응답하도록 지시한다.

확대 이미지는 최대 1600×1000 픽셀, 최대 6배 렌더링이며 한 요청의 총 픽셀 예산(약 3200만)에 맞춰 조정한다. PNG 합계가 16MB를 넘으면 마디를 나눠 선택하도록 오류를 반환하며 자동 추가 호출은 하지 않는다. 서버 런타임에 `pdfjs-dist`와 `@napi-rs/canvas`를 추가했으므로 다른 서버에 반영 시 `npm ci`로 의존성을 설치한다. DB 변경은 없다. 이미지 데이터는 작업 결과·진단 다운로드에 저장하지 않으며 `measureCrops`에 개수 확인용 파트·페이지·마디·크기·좌표만 남긴다. 이미지 입력 토큰은 추가되므로 재분석 안내에도 이를 표시한다.

셋잇단 범위가 모호하면 인쇄된 3 근처의 같은 성부·같은 길이 이벤트 3개를 한 그룹으로 추정할 수 있도록 요청한다(동시 코드음 3개를 리듬 3개로 세지 않음). 점음표·점쉼표의 길이와 잇단 비율을 함께 계산한다. 불확실한 붙임줄은 두 음표를 유지한 채 생략할 수 있으며 `TIE_OMITTED` 경고로 알린다.

`reading:estimated`의 마디 초과는 `ESTIMATED_BAR_OVERFLOW` 경고와 함께 내보낼 수 있다. 음표를 자르거나 다음 마디로 몰래 옮기지 않고 `measureLengths`를 늘려 원래 이벤트를 보존한다. 다른 파트도 동일 마디 길이를 맞추고 추가된 구간을 쉼표로 채워 마디 번호·시간 정렬을 유지하며 `ESTIMATED_BAR_ALIGNMENT`를 알린다. 표기 박자표는 유지되므로 사용자가 리듬과 마디 길이를 수정해야 하는 편집용 결과다. 겹치는 이벤트, 잘못된 줄·음정, 읽지 못한 음표 등은 계속 차단한다. 확정(`complete`) 마디의 초과까지 자동 허용하지는 않는다.

읽힌 줄·프렛·노트 순서는 유지하면서, 꼬리 없는 타브 기둥의 길이가 모호한 경우 4분음표를 먼저 대입하고 맞지 않으면 2분음표 조합을 확인하도록 요청한다. 점음표·점쉼표는 1점 3/2배, 2점 7/4배이며 눈에 보이는 점을 근거로 한다. 명확한 빔·꼬리·셋잇단 표시는 바꾸지 않고 박자 합만 맞추려고 음표·쉼표를 만들어 넣지 않는다.

사용 가능한 리듬 후보는 `reading: estimated`로 반환할 수 있다. `uncertainties`에 어떤 리듬을 선택했는지 남기고 `RHYTHM_ESTIMATED` 경고를 표시한다. 서버는 리듬 추정 사유를 `blocking:false`로 구분하며, 마디 길이·겹침·음정/타브 위치 등의 검사를 통과하면 출력과 악보 적용을 허용한다. 읽지 못한 노트나 모순된 타이밍은 계속 차단한다. 추정 결과의 상세 위치는 완료 후에도 PDF 검토 화면에서 확인할 수 있으며, 추정했다는 사실을 원본 인식 성공으로 간주하지 않는다. 자동 유료 재호출은 추가하지 않는다.

음표 응답의 각 마디에 `uncertainties` 배열을 추가했다. 항목은 `kind`(fret/string/rhythm/tuplet/tie/technique/other), 한국어 `reason`, `bounds`(페이지 기준 0~1000의 기호 영역 또는 null), `eventIndex`(알려진 경우 1부터의 이벤트 순서 또는 null)를 담는다. 불확실한 마디에는 이유를 하나 이상, 확실한 마디에는 빈 배열을 요청한다. 추측 위치를 확정 오류로 표현하지 않는다. 서버는 이유 길이·유형과 좌표를 검사하며, 잘못되거나 마디 밖에 있는 좌표는 기호 표시에서 제외한다. 같은 마디에 여러 기호의 상세 이유를 보존한다.

음표 분석 실패 시 왼쪽 PDF에는 구조 단계의 마디 경계와 의심 기호를, 오른쪽에는 마디별 이유 목록을 표시한다. 목록 클릭으로 페이지·마디 포커스를 이동하고 체크박스로 선택한 마디를 일괄 재분석한다. 상세 위치가 없는 기존 결과는 마디 전체 표시로 대체하며, 예전 진단에 없던 세부 사유를 복원하거나 만들어내지 않는다. 파일 선택·기존 결과 보기로 돌아가는 버튼을 제공한다. 새 상세 응답은 새로운 분석부터 받을 수 있다.

음표 단계에서 불확실한 마디를 반환하기 전에 두 차례 추가 검토(줄·프렛·X 확인, 리듬·동시음·붙임줄·마디 길이 확인)를 수행하도록 요청한다. 이는 단일 응답 안에서의 지시이며 실제 내부 검토 횟수를 검증하지 않는다. 자동 API 재시도는 없다.

오류 목록에서 파트·페이지·마디를 체크한 후 선택 마디 일괄 재분석이 가능하다. `POST /score-pdf/jobs/:id/reanalyze-batch`의 본문은 `{measures:[{part,page,measure},...]}`이며 최대 128개, 중복 대상은 한 번만 처리한다. 선택한 마디의 구조·확대 이미지와 범례 문맥만 1회 전송하고, 응답의 파트·마디 일치 여부를 검사한 후 해당 초안만 교체한다. 선택하지 않은 파트와 마디는 유지한다. 기존 단일 페이지·마디 재분석 API도 유지한다.

구조 호출 이후 `structure_review` 상태에서 자동 진행을 멈춘다. 결과의 각 마디에는 `system`(페이지 내 악보 줄, 1부터)과 `bounds: [left, top, right, bottom]`(페이지 좌상단 원점, 0~1000 좌표)이 있다. PDF 캔버스 위에 마디 상자를 표시하며 선택·다시 그리기·추가·분할·다음 마디와 병합·삭제·좌표/페이지/줄 수정을 지원한다. 마디 수 변경 시 해당 파트 번호는 첫 번호부터 연속 재부여한다.

수정한 구조는 `POST /score-pdf/jobs/:id/structure/confirm`에 `{structure, revision}`으로 전달한다. 서버는 소유자, 확인 대기 상태, 최신 revision, 좌표 범위, 앞뒤 순서, 같은 줄 마디 겹침, 다른 줄 영역 겹침을 검사한다. 이 검증이 통과하고 사용자가 확인한 뒤에만 음표 API를 1회 호출한다. 확인 전 편집/조회에는 추가 비용이 없다. 구조를 다시 분석하는 버튼은 새 호출 1회가 발생한다. 정상 구조 검사는 원본 이미지의 음악적 의미까지 판별하지는 않는다.

전체 추출은 **구조 전용 호출 → 음표 전용 호출 → 서버 검증**으로 진행한다. 각 호출에 PDF 전체 Base64와 `detail: high`를 유지한다. 구조 결과의 파트 ID·악기·카포·마디 번호·페이지·박자표를 음표 요청에 전달하고 변경·누락·추가 여부를 검사한다. 음표 단계에서는 주법 추출을 제외하고 줄·프렛·X·리듬에 집중한다.

각 마디의 `reading`은 `complete` 또는 `unreadable`이다. `complete`의 빈 이벤트만 확실한 온마디 쉼표로 간주한다. 미인식·불확실 경고, 빈 박자, 마디 초과, 같은 성부 겹침, 같은 줄 동시 중복, 불완전한 셋잇단 분할은 변환 전에 검토 항목으로 반환한다. 자동 쉼표 보정으로 정상 완료 처리하지 않는다. 셋잇단 그룹 검사는 현재 연속된 동일 길이 분할을 기준으로 한 보수적인 검사이며 복잡한 혼합 잇단음표는 추가 지원이 필요하다.

실패한 초안도 메모리에 보관해 해당 페이지·마디만 명시적으로 재분석할 수 있다. 기존 구조를 재사용하므로 이때는 음표 호출 1회다. 다른 마디는 유지하며 모든 오류가 해소된 경우에만 변환·다운로드·적용이 가능하다. 구조 자체가 틀린 경우 전체 다시 추출이 필요하다. 자동 재호출은 없으며 각 단계 토큰은 누적 계산한다. 진단 JSON의 `stages`에 단계별 응답을 포함한다. 작업·구조·초안은 서버 재시작 또는 1시간 만료 시 사라진다. DB 변경은 없다.

현재 스키마에는 반복 이동, 별도 문서 순서, 음자리표 변경, 기본값 출처, 못갖춘마디의 명시적 길이 필드가 없다. 지원하지 않는 구조는 경고와 검토로 남긴다. 모델 인식 정확도는 실제 악보 결과로 별도 확인해야 하며, 구조 검사 통과만으로 원본과 일치함을 보장하지 않는다.
# 강제 추론

## PDF 선에 근거한 가로 경계 보정

구조 API 응답 뒤 서버가 PDF를 페이지별 제한 해상도로 렌더링하고 실제 수평 오선·타브 줄과 전체 높이를 가로지르는 얇은 세로 마디선을 찾아 가로 경계를 보정합니다. 페이지 끝이나 균등 분할은 사용하지 않습니다. 4·5·6줄을 구분하고 양손 키보드는 두 보표에 공통으로 확인되는 마디선을 사용합니다. 음표 머리에 붙은 기둥은 넓은 머리의 잉크 흔적으로 걸러냅니다. 세로 높이와 마디 번호·개수는 바꾸지 않습니다.

수평선이 너무 짧거나 흐릿함, 회전·복잡한 배치, 내부 마디선 후보 부족, 기존 위치와 지나치게 먼 후보 등 확신이 부족한 줄은 기존 경계를 유지하여 수동 검토합니다. `boundaryAlignment` 진단에는 파트·페이지·악보 줄별 보정 전후 좌표를 남깁니다. 초기 구조 분석에만 적용하며 사용자가 수정·확정한 경계와 재분석 경계를 자동으로 덮어쓰지 않습니다. 추가 OpenAI 호출이나 DB 변경은 없습니다.

## 여러 마디 쉼표와 좌우 경계

모든 악보 종류는 숫자가 있는 여러 마디 쉼표를 `restCount`(2~128)로 반환합니다. 예를 들어 77마디 위의 10은 `number:77, restCount:10`으로, 구조 확인 화면에는 실제 쉼표 영역 하나와 `77~86 · 10마디 쉼표`를 표시합니다. 일반 마디는 `restCount:null`입니다. 음표 단계는 이 묶음을 `reading:complete, events:[], uncertainties:[]`로 유지하며 변환기가 77~86마디의 온마디 쉼표로 확장합니다. 명시된 쉼표 묶음 자체에는 누락·추정 경고를 만들지 않습니다. 양손 키보드와 드럼의 두 성부도 같은 길이로 쉽니다. 묶음은 나누기·인접 마디 합치기에서 제외하고 재분석은 시작 마디로 요청합니다. DB 변경은 없습니다.

좌우 여백에는 이전·다음 마디의 음표 머리·타브 숫자/X·기둥·빔이 포함되지 않도록 요청합니다. 이웃 음표가 들어오면 해당 경계를 실제 마디선 쪽으로 조정하며, 대상 마디의 첫·마지막 음표를 자르거나 마디 번호를 바꾸지 않습니다. 위아래 꼬리·셋잇단 숫자 여유를 확보하기 위해 가로 경계까지 넓히지 않습니다. 이는 모델의 경계 판단 지시이며 별도의 자동 영상 검출이나 유료 재검토 호출을 추가하지 않습니다.

## 드럼 오선

- 음표 응답의 각 드럼 타격은 `position:[x,y]`로 음표 머리 중심을 페이지 기준 0~1000 좌표로 반환합니다. 위치를 확신할 수 없으면 null입니다. 서버는 마디 밖·유효하지 않은 좌표를 제외하고 `recognizedHits`로 제공합니다. 원본 검토 화면에서 초록 원 표시를 켜고 끌 수 있으며 정상 마디도 선택해 재분석할 수 있습니다. 모델의 추정 위치이므로 독립적인 이미지 검출이나 누락 없음의 보장이 아닙니다. 기존 분석 결과에 없던 위치를 만들어내지 않으며, 새 분석부터 위치 응답을 받을 수 있습니다. 이 필드는 출력 토큰이 일부 늘어납니다.

- 최초 음표 분석은 전체 PDF만 사용하며 확대 이미지는 재분석할 때만 첨부합니다. 성부별 점검 응답은 유지합니다. 자동 추가 API 호출은 없습니다.
- 위 성부를 끝까지 읽은 뒤 아래 성부를 독립적으로 읽도록 요청합니다. `drumCoverage`에 성부별 판독 상태와 모델이 센 타격 수를 받고 반환된 노트 수와 비교합니다. 이는 모델의 자기 보고를 검사하는 것이므로 원본의 모든 누락을 검출한다고 보장하지 않습니다.
- 읽을 수 있는 타격은 악기 종류가 불확실해도 추정 노트와 경고로 남깁니다. 확인되지 않은 빈 박자는 편집용 쉼표로 채우되 실제 쉼표로 확인했다고 간주하지 않습니다. `DRUM_HIT_OMISSION` 또는 `DRUM_COVERAGE_MISSING`이 있으면 완료 후에도 PDF 검토 화면을 먼저 표시하며, 유효한 초안은 다운로드할 수 있습니다. 지원하지 않는 음표 값이나 시간 겹침 등 변환 불가능한 데이터는 계속 차단합니다. 자동 재호출과 DB 변경은 없습니다.

- 악보 종류 `드럼` / `drums`는 한 드럼 세트의 위·아래 성부를 하나의 논리 파트로 분석합니다. `staff:upper/lower`별 시작 박자는 같은 마디의 0이며 성부별 박자 합계를 검사합니다. 출력은 기존 `drumVoices` 연결을 사용하고 파트 이름은 `드럼 1`, `드럼 2`로 통일합니다.
- 원본 범례·악기명을 우선하고 음표 위치와 머리 모양을 함께 보아 지원 GM 드럼 번호로 변환합니다. 닫힌/열린/페달 하이햇(42/46/44), 킥·스네어·탐·심벌 등을 구분합니다. X 머리는 타브 고스트노트가 아닌 실제 타격입니다. 조표는 0이며 선율 음높이로 해석하지 않습니다.
- 보표 밖 심벌·킥·페달 음표, 꼬리 끝과 아래 셋잇단음표 숫자를 마디 영역에 포함하도록 요청합니다. 화음처럼 동시에 치는 타격을 묶고, 쉼표·점·빔·셋잇단음표를 성부별로 계산합니다.
- 오선 간격에 대한 음표 머리 중심 위치와 머리 모양을 문서 전체에서 비교합니다. `Closed H.H. →`·`Ride →` 지시는 같은 파트의 다음 변경 지시까지 유지하며, 국소 열림 원/닫힘 + 표시는 해당 하이햇에 적용합니다. 위쪽 X와 아래쪽 페달 X를 기둥 방향만으로 같은 악기로 처리하지 않습니다.
- 사선 음표 머리·기둥 사선 롤·리듬 반복 슬래시를 구분합니다. 문맥상 확인된 스네어 림샷은 `snare-rimshot`, 스네어·탐의 롤 표시는 `snare-roll2/roll3`, `tom-roll2/roll3` 개별 노트 라벨로 받아 기존 `drumTechnique`에 전달합니다. 동시 타격의 다른 악기에 같은 주법을 적용하지 않으며 기본 박자 길이를 유지합니다. 강제 추론은 이 세부 라벨을 제거합니다. 스틱 지정, 불확실한 버즈 롤·그루브 반복은 생략하고 검토 경고를 남깁니다. 지원하지 않는 악기 번호나 타브 값은 검토 대상으로 분류합니다.
- 마디 재분석·확대 이미지·강제 추론이 드럼 프로필을 유지합니다. DB 변경은 없으며, 모의 API 테스트는 실제 PDF 인식 정확도를 보장하지 않습니다.

## 키보드 양손 오선

- `키보드 (양손)` / `keyboard` 작업은 큰보표의 오른손·왼손을 하나의 논리 파트와 같은 마디로 읽습니다. 구조 영역은 두 보표와 덧줄·꼬리·셋잇단음표 숫자를 함께 포함합니다. 파트 이름은 `키보드 1`, `키보드 2`로 통일합니다.
- 음표 분석은 `instrument:piano`, `staff:right/left`로 두 손을 구분하며, 각 손의 마디 시작은 0박입니다. 화음은 동시 이벤트, 성부는 별도 시간축입니다. 변환기는 기존 `keyboardStaves` 연결과 오른손 `piano` / 왼손 `pianoBass`를 사용합니다.
- 첫 번째로 확인 가능한 마디의 조표를 양손 음자리표 뒤에서 확인합니다. 읽은 조표를 유지하고, 확인할 수 없으면 C장조(조표 0)로 설정하여 `KEY_DEFAULT_C` 경고를 남깁니다. 서버도 null 조표를 0으로 보정하고 확정한 초기 조표를 음표 분석·재분석에서 유지합니다.
- 임시표를 조표와 구분하고, 각 보표의 실제 음자리표로 음높이를 계산합니다. 조표·음자리표 변경은 실제 소리를 보존하면서 검토 경고를 요청합니다. 재분석·확대 이미지·강제 추론을 지원하며 서버 DB 변경은 없습니다.

## 일반 오선 (보컬·기타 악기)

- PDF 변환 창에서 보컬과 기타 악기용 오선을 `일반 오선 (보컬·기타 악기)` 하나로 선택합니다. 기존 작업과 호환되도록 내부 종류 `vocal-staff`를 유지하며 DB 변경은 없습니다.
- 타브 전용 요청문 대신 일반 오선 요청문과 `instrument: standard` 응답 스키마를 사용합니다. 가사가 없는 악기 오선도 포함하며, 타브·양손 키보드 큰보표·드럼은 별도 종류로 처리합니다. 독립 파트와 인쇄된 악기 이름을 유지하고 이름이 불명확하면 `오선 1`, `오선 2`로 요청합니다. 타브와 오선이 같은 연주를 중복 표기하면 오선만 한 번 읽습니다.
- 음자리표, 덧줄, 조표, 임시표, 옥타브 기호로 실제 MIDI 음높이를 읽습니다. 가수의 성별만으로 옥타브를 바꾸지 않으며, 음표·쉼표·점·잇단음표·붙임줄의 박자를 검사합니다. 경계에는 덧줄과 음표 꼬리 끝, 셋잇단음표 숫자를 포함합니다.
- 음표의 `pitch`가 필요하고 타브 줄·프렛·드럼 값은 null입니다. 가사와 세부 주법 추출은 이번 버전에 포함하지 않습니다. 재분석은 같은 보컬 파트와 마디를 유지하고 확대 이미지를 사용하며, 강제 추론 결과는 추정 경고를 남깁니다.
- 현재 출력 모델은 음자리표 변경과 파트별 조표 변경을 온전히 저장하지 못합니다. 실제 음높이를 우선 보존하고 해당 변경에는 검토 경고를 요청합니다. 실제 PDF 정확도는 별도 샘플 확인이 필요하며, 모의 테스트 통과가 인식 정확도를 뜻하지 않습니다.

## 타브가 없는 중간 구간

기타·베이스 타브의 원본에서 타브 자체가 생략된 구간은 후속 마디의 인쇄 번호를 유지합니다. 구조 결과는 없는 타브 영역을 만들지 않고 번호를 건너뛸 수 있으며, 변환기가 번호 사이를 온마디 쉼표로 채우고 `MISSING_MEASURE_REST` 경고를 남깁니다. 박자표는 직전 값을 상속합니다. 마디 중복·역순과 보이지만 읽지 못한 타브는 계속 검증하며, 마지막으로 확인된 마디 뒤의 알 수 없는 길이를 임의로 추가하지 않습니다.

## 악보 종류: 베이스 타브

- 변환 창에서 `베이스 타브 (4현)`을 선택하면 작업에 `bass-tab` 종류가 저장됩니다. 같은 PDF라도 기타 분석 작업과 분리하며 구조 분석·음표 분석·재분석·강제 추론 모두 선택한 종류를 유지합니다.
- 4개 수평선을 위에서부터 1~4번 줄로 읽습니다. 기본 튜닝의 실제 소리는 G2·D2·A1·E1(MIDI 43·38·33·28)이며, 기타처럼 6현으로 읽거나 옥타브를 추가 보정하지 않습니다.
- 기본 `bass`, 명시된 하프다운 `bassHalfDown`, Drop D `bassDropD`를 지원합니다. 파트 이름은 `베이스 1`, `베이스 2` 순서로 통일합니다.
- 기타에서 사용한 프렛·고스트노트·화음·쉼표·점음표·셋잇단음표와 경고 검증을 공유합니다. 슬랩 등 세부 주법과 5·6현 베이스는 이번 지원 범위에서 제외합니다. 서버 DB 구조 변경은 없습니다.

- 불확실한 마디를 선택하고 `선택한 마디 재분석` 우측의 `강제 추론`을 누릅니다. 같은 배치 API에 `forceInference: true`를 전달하며, 선택한 마디의 확대 이미지와 구조·문맥으로 한 번 요청합니다. 전체 PDF는 다시 첨부하지 않습니다.
- 일반 분석에서도 프렛이 읽히면 가장 가까운 현을 추정할 수 있습니다. 범위가 불명확한 셋잇단음표는 인근의 같은 길이인 연속 세 이벤트로 추정하며, 코드는 한 이벤트로 셉니다. 불명확한 붙임줄은 생략할 수 있습니다.
- 강제 추론에서는 줄·프렛·박자를 최선의 후보로 채우고, 주법·붙임줄·이음 표기는 제거합니다. `FORCED_INFERENCE` 경고와 마디별 사유를 남기므로 원본 대조와 사용자 편집이 필요합니다.
- 강제 추론은 정확성을 보장하지 않습니다. 음표 자체를 구별할 수 없는 마디, 유효하지 않은 좌표·음표 값·겹치는 시간 등 변환이 불가능한 데이터는 계속 검증합니다. 이후 다른 마디를 일반 재분석해도 기존 강제 추론 마디의 추정 상태는 유지됩니다.

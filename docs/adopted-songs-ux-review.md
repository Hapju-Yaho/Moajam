# 채택곡 기능 구조 및 UX 검토

검토일: 2026-09-28. 아래 검토 본문은 개선 전 구현을 기록한 것이다. 이후 사용자 요청에 따라 아래 항목을 구현했다. 실제 다중 계정 협업과 모바일 기기의 녹음·재생은 별도 검증이 필요하다.

## 후속 개선 반영

- 목록: 활동곡/보관곡 집계, 실제 참여자, 정렬, 다음 합주, 빈 결과 초기화.
- 메인: 내 준비 상태와 담당 할 일을 우선 배치하고 다음 합주·팀 준비·결정 내용을 요약. 대표 영상은 펼쳐 보기.
- 개요: 곡 제목/아티스트/목표/대표 영상 및 편곡의 읽기·편집 상태 분리. 파트 미참여 구분. 할 일 담당자와 완료 필터.
- 의견: 내용·작성자·답글 검색, 내 의견 필터, 결정에서 할 일로 중복 없이 연결.
- 자료: 링크 검색·수정·중복 검사·영상 미리보기 및 작성자/관리자 권한 적용. 작성자가 없는 기존 링크는 관리자만 편집.
- 연습: 곡 상세 탭 내부 진입, 미참여/보관곡의 개인 연습 허용, 웹 연습 BPM 분리, 곡 자료 음원 가져오기.
- 합주 기록: 예정/완료/취소 구분, 완료 합주의 곡별 회고, 예정 합주에 곡 추가.
- 공통 이동: 탭 URL, 새로고침·뒤로가기·공유 유지, 악보 편집에서 자료로 복귀 및 밴드 BPM 가져오기.

남은 확장 항목: 악보의 자료 직접 게시, 파일 버전/최신본, 멘션·읽지 않은 의견 알림, 편곡 변경 이력, 합주 세션 할 일과 곡 할 일의 양방향 동기화, 모바일 서버 협업. 이 항목들은 이번 개선에 포함하지 않았다.

| ----------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 채택곡 목록 | 전체·연습 중·준비 완료·보관함, 제목/아티스트 검색, 파트 준비도, 내 파트, 의견 수, 연습 시작                                    | 곡 추가는 곡 추천으로 이동. 관리자가 추천곡을 채택하면 목록에 추가                                |

| 연습        | 웹: 여러 음원 동시 재생, 트랙별 볼륨/뮤트/솔로/오프셋, A–B 반복, 녹음, 메트로놈, 구간 메모, 다운로드, 서버 연결 시 밴드에 공개 | 곡 상세 탭 내부가 아니라 개인 연습실 화면으로 이동. 모바일은 음원별 재생·녹음·메모 중심           |
| 합주 기록   | 해당 곡이 세트리스트에 연결된 합주 목록, 합주 기록 열기                                                                        | 합주 화면에서 참석, 확인사항, 녹음, 메모, 담당자별 할 일 관리                                     |

사용 흐름은 `추천 → 채택 → 파트·편곡 설정 → 의견/자료 공유 → 개인 연습 → 합주 → 다음 준비`이다. 기능은 대부분 있지만 각 단계의 결과가 다음 단계로 이어지는 연결은 아직 약하다.

## 먼저 개선할 부분

### 1. 연습 진입과 복귀 흐름 정리 — 우선순위 높음

- 상세의 **연습** 탭을 누르면 개인 공간 연습실로 이동하며 모든 밴드의 곡 선택기가 나온다. 돌아오면 상세의 이전 탭 대신 메인부터 열린다.
- 보관된 곡이나 본인이 미배정인 곡에도 연습 버튼이 보이지만, 연습 화면은 참여 중이고 보관되지 않은 곡만 찾는다. 버튼을 눌렀는데 “곡을 찾을 수 없어요”가 나올 수 있다.
- 제안: 곡 상세에서 들어온 연습실은 곡과 밴드 맥락을 유지하고 곡 선택기를 접는다. 미배정·보관 상태에는 사유와 가능한 다음 행동(참여 배정 요청/연습 재개)을 표시한다.
- 완료 기준: 모든 연습 버튼의 대상이 실제로 열리며, 복귀 시 이전 곡과 작업 위치가 유지된다.

### 2. 편곡 정보와 실제 연습 설정 연결 — 우선순위 높음

- 개요의 BPM은 곡 문서에 저장되지만, 연습실 메트로놈은 개인 환경설정 BPM을 사용한다. 악보 편집기는 별도 BPM을 가진다.
- 제안: **밴드 기준 BPM**과 **내 연습 BPM**을 구분하고, 연습 시작 시 기준 값을 적용하거나 개인 설정을 유지할지 명시한다. 악보에도 기준값 가져오기 기능을 둔다.
- 완료 기준: 같은 곡의 기준 BPM이 화면마다 다르게 보이지 않고, 개인적으로 낮춘 연습 속도는 밴드 편곡을 덮어쓰지 않는다.

### 3. 자료 → 연습 연결 — 우선순위 높음

- 자료 보관함과 연습실 트랙은 별도 저장소다. 공유 음원을 자료에서 확인한 뒤 연습실에 직접 불러오는 동작은 없다.
- 악보 편집은 곡 식별자를 받아 개인 악보를 저장하지만, 저장한 악보가 자동으로 밴드 자료에 추가되지는 않는다. 현재는 내보낸 뒤 업로드해야 한다.
- 연습 녹음을 밴드 자료에 공개하는 흐름은 있으나, 공개된 자료에서 연습실로 되돌아오는 연결은 부족하다.
- 제안: 자료에 **연습에 사용**, 악보에 **밴드 자료로 내보내기**, 녹음 공개 후 **공개한 자료 보기**를 제공한다. 업로드 전에 공개 범위를 명확히 선택하게 한다.

## 기능상 빠져 있거나 연결이 약한 부분

1. **결정의 후속 행동**: 결정 표시만 있고 결정 요약, 적용 구간, 담당자, 기한, 편곡/할 일로 보내기가 없다. “2절은 드럼만” 같은 결론이 의견에만 남기 쉽다.
2. **곡별 합주 회고**: 현재는 연결된 합주의 날짜와 제목을 거쳐 합주 전체로 이동한다. 곡별 녹음 구간, 그날의 문제점, 결정 사항, 다음 액션이 상세에 요약되지 않는다. 예정/완료/취소된 합주도 같은 목록에 섞인다.
3. **확인사항 연결**: 곡의 확인사항과 합주 세션의 확인사항/할 일은 별도 문서다. 같은 일을 두 번 적게 될 수 있다. 공통 항목을 불러오고 완료 상태를 연계할 규칙이 필요하다.
4. **자료 버전과 편집 권한 안내**: 파일 버전/최신본 표시, 파트별 분류, 레퍼런스 링크 수정이 없다. 일반 레퍼런스는 작성자 정보 없이 멤버 누구나 삭제할 수 있으므로 팀 운영 규칙과 맞는지 결정해야 한다.
5. **의견 검색과 알림**: 멘션, 검색, 읽지 않은 의견 표시, 결정 알림이 없다. 영상 링크는 의견당 하나이며 특정 연주 구간을 묶는 구조도 없다.
6. **동기화와 변경 이력**: 서버 저장·충돌 검사는 있지만 다른 멤버 변경의 실시간 구독, 편곡 버전 이력, 복원 UI는 없다. “저장됨”과 “팀의 최신 내용”을 구분할 필요가 있다.
7. **준비 완료의 기준**: 현재는 참여자의 READY 개수로 집계한다. 준비 기준/목표일/막힌 이유는 없다. 미참여 멤버가 개요에서 “준비 전”처럼 읽힐 수 있어 미참여와 미준비를 분리해야 한다.
8. **웹·모바일 기능 차이**: 모바일 서버 인증/협업 연결은 아직 비활성이다. 파일 공유와 연습 도구 범위도 웹과 다르므로 두 플랫폼에서 같은 수준으로 지원하는 항목을 명시하고 우선 범위를 정해야 한다.

## 권장 진행 순서

1. 연습 진입 예외, 복귀 위치, BPM 기준, 자료 불러오기 연결을 먼저 정리한다.
2. 메인 상단을 “다음 합주까지 내가 해야 할 일” 중심으로 정리하고 중복 이동 수단을 줄인다.
3. 결정 → 편곡/할 일 → 합주 회고를 연결한 뒤 변경 이력·알림·자료 버전을 확장한다.

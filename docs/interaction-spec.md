# 화면별 기능 명세와 구현 상태

기준: 2026-09-18. 현재 활성 서비스의 구현을 기록한다. `legacy/`는 참고 원본이며 수정하지 않는다.
제품 구조는 [워크스페이스 기획](./workspace-structure-spec.md), 서버 연결은 [협업 환경 설정](./collaboration-setup.md)을 참고한다.

## 공통 구조

- 개인 공간: 홈, 합주 일정, 참여 곡, 연습실. 여러 밴드의 내 정보를 통합한다.
- 밴드 공간: 홈, 곡 추천, 채택곡, 합주, 멤버. 사이드바에서 밴드를 전환하거나 만든다.
- 밝은 사이드바, 화면별 탑바, 모바일 하단 메뉴. 본문 400, 라벨·버튼 500, 제목 최대 600.
- 개발 예정 오버레이는 제거했다. 실행 환경이 필요한 기능은 버튼 옆에 조건과 실패 이유를 표시한다.
- 곡·합주 URL은 밴드와 항목 ID를 유지한다. 없는 밴드·곡·합주는 별도 안내한다.
- 로딩, 빈 목록, 권한 부족, 파일 오류, 저장 실패를 구분한다. 저장 충돌 시 변경을 자동으로 덮어쓰지 않는다.

## 저장과 사용자

| 환경              | 동작과 범위                                                                                                      |
| ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| 웹 환경 변수 없음 | 샘플 사용자 m1, 샘플 밴드. 밴드 기록은 localStorage, 파일·연습·악보는 IndexedDB에 보관                           |
| 웹 서버 설정 있음 | 기본 자동 임시 로그인, 정식 인증은 카카오 OAuth. Nest API로 멤버십·밴드 문서·초대·자료·분리 작업·앱 내 알림 연결 |
| 모바일            | 밴드 기록·설정·자료·녹음을 앱 문서 디렉터리에 보관. 서버 인증·공동 데이터 어댑터는 아직 웹에만 연결              |
| 개인 파일         | 웹에서는 계정별 저장 키를 사용. 기본 비공개이며 사용자가 공개한 트랙만 밴드 공유 자료가 됨                       |
| 공동 수정         | 문서 revision을 검사해 오래된 쓰기는 409로 거절. 실패한 화면 변경은 백업 후 서버 기록으로 교체 가능              |

서버 데이터는 최초 진입과 명시적 새로 불러오기에서 갱신한다. 실시간 구독이나 자동 병합은 아직 없다.
여러 문서와 멤버 변경은 순차 저장이므로 부분 성공 가능성이 있다. 실패 시 상태를 표시하며 성공으로 안내하지 않는다.
현재 저장소에는 실제 `.env`가 없으므로 원격 연동 코드는 실서비스 검증 전이다.

## 구현 경계와 남은 개발

아래는 환경값을 넣는 것만으로 해결되지 않는 후속 개발이다. 전체 제품 기능 완료로 간주하지 않는다.

- WebSocket 실시간 구독, 충돌 병합 UI와 장기 변경 이력. 현재는 15초 폴링과 여러 문서의 원자적 저장을 지원한다.
- 계정 삭제·이관. 이메일·비밀번호 흐름은 제거했고 카카오 로그인 화면과 개발용 임시 로그인을 제공한다. 카카오 실계정 검증은 설정 후 필요하다.
- 변경 알림 자동 생성, 합주 하루 전 예약 알림, 실제 이메일·푸시 채널, 문의 접수.
- 합주 할 일 기한 편집과 결정 사항의 다음 합주 자동 이관.
- 연습 파형, 장치 선택, 지연 측정, 악보 페이지 뷰어·자동 넘김, 팀 Take를 직접 불러와 비교하기.
- 분리 작업은 단일 서버 프로세스용. 다중 워커 lease·재분배, 사용자별 저장 용량·요금, 분리 품질 분석, MP3 변환은 없음.
- 악보는 기본 단선율과 4/4 출력. 다성부·꾸밈음·잇단음표 가져오기는 거절한다. 표준 악보 조판, 페이지 단위 PDF, 영구 revision 이력은 없음. 인쇄/PDF 버튼은 브라우저 인쇄를 연다.
- 모바일도 서버 인증·협업·자료·추출 요청 API를 사용한다. 멀티트랙 동시 재생·메트로놈·정밀 악보 재생은 웹과 기능 차이가 있다.
- 데모 기록은 기기 안에만 저장한다. 서버 모드의 SQLite DB와 파일 백업은 [실행 안내](./runtime-storage.md)를 따른다.

## 검증

- 전체 워크스페이스 타입 검사, ESLint 통과.
- 웹·서버 빌드 통과. 웹 번들 크기 경고는 남음.
- 워크스페이스·협업 정책·MusicXML 자동 테스트 29개와 서버 상태 테스트 1개 통과.
- 브라우저: 편곡 수정 후 새로고침 복원, 악보 입력·Undo/Redo·저장 복원, 곡 연습실 문맥 유지, 테스트 WAV 추가·새로고침·실제 재생 확인.
- 미검증: 실제 DB migration, 두 계정 동시 사용, Supabase 비공개 저장소, Demucs 실행, 모바일 실기기 녹음·공유. 운영 배포는 하지 않음.

# PDF 악보 변환

## 실행 설정

`apps/server/.env.local`에 설정 후 서버를 재시작한다. 키는 서버에서만 사용한다.

```env
OPENAI_API_KEY=발급받은_키
OPENAI_SCORE_MODEL=gpt-5-mini
OPENAI_SCORE_MAX_OUTPUT_TOKENS=12000
```

키가 비어 있어도 서버는 실행된다. 키를 입력하거나 서버를 시작하는 것만으로 API를 호출하지 않는다.
모델은 PDF 이미지 입력과 Structured Outputs를 지원해야 한다. 기본 출력 한도는 12,000토큰이며 환경 변수로 1,024~64,000 사이에서 변경한다.
출력이 잘리면 일부 결과를 적용하지 않고 오류를 표시한다. 출력 한도에는 모델의 추론 토큰도 포함될 수 있다.

## 사용 흐름

개인·밴드 악보 편집 → 가져오기 → PDF.

1. 파일 선택/드래그 또는 **내 밴드에서 가져오기**로 PDF를 선택한다. 브라우저에서 페이지 수를 확인한다.
2. **악보 추출**을 누르면 PDF를 서버에 업로드하고 분석을 시작한다. 이 시점에 API 요금이 발생한다.
3. 서버가 전체 PDF를 Base64로 전송한다. GPT의 JSON 응답을 검사한 뒤 모아잼 악보 데이터로 변환한다.
4. 파트·마디별 악보 미리보기, 경고와 누적 입력/출력 토큰 수를 확인한다.
5. 선택한 파트를 현재 프로젝트의 대상 파트·시작 마디에 삽입하거나, **전체 악보로 교체**한다. 기존 음표가 있으면 별도 확인 창을 표시한다. 적용 후 프로젝트 저장은 별도로 한다.
6. .moajam / .musicxml / .mid를 고르고 **다운로드할 파일**에서 필요한 파트를 선택한다. 기본은 전체 선택이다.
   파트가 여러 개면 `곡이름_파트이름.확장자`로 각각 다운로드한다. 키보드 양손과 드럼 위/아래 성부는 한 악기 파일로 유지한다.
   다운로드·적용은 기존 결과를 사용하며 추가 GPT 호출이 없다.

특정 페이지·마디 재분석은 해당 범위만 다시 인식해 기존 결과와 병합한다. **전체 PDF를 다시 전송하므로 추가 API 요금이 발생한다.** 실패하면 이전 변환 악보를 유지한다.
자동 API 재시도는 없다. 실패 후 사용자가 **다시 추출**을 누르면 새 유료 요청이 발생할 수 있다.
연결 시간 초과는 서버가 실제 사용 여부를 확정할 수 없으므로 OpenAI 사용량도 확인한다.

## 지원과 검증 범위

- 최대 20MiB / 40페이지의 암호 없는 PDF. 인식 결과는 최대 논리 파트 8개, 128마디, 음표·쉼표 합계 2,000개.
- 일반 오선, 지원 튜닝의 기타·베이스 TAB, 드럼 위/아래 성부, 키보드 양손, 별도의 기타 파트를 변환한다.
- 시작 박·길이는 4분음표 기준 분수로 받고 1/48박 격자를 검증한다. 셋잇단음표를 중복 축소하지 않는다.
- 마디 초과, 지원하지 않는 박자, 음높이 누락, 서로 다른 길이로 겹치는 같은 보표의 성부는 오류로 처리한다.
- 마디가 하나도 인식되지 않은 파트는 경고와 함께 제외한다. 모든 파트가 비어 있으면 실패로 표시하며, 임의의 빈 악보를 만들지 않는다.
- 원본 마디 번호가 55처럼 중간부터 시작해도 편집 악보에서는 1마디로 재배치한다. 원본 번호는 페이지·마디 재분석에 보존한다.
- 비어 있는 박은 보이는 쉼표로 채우고 경고한다. 숨은 박을 덧붙여 마디를 늘리지 않는다.
- 주법은 종류만 인식한다. 벤딩 높이·시간은 요청하지 않고 필요한 기본값을 사용한다.
- 반복 기호, 일부 코드음만의 붙임줄, 지원하지 않는 튜닝/복잡한 다성부는 경고 또는 오류로 안내한다.
- 박자 변경은 마디별 길이를 보존하지만 현재 편집기의 표시 한계는 경고한다.
- MusicXML/MIDI는 기존 내보내기를 사용한다. MIDI는 TAB 운지·모든 주법 표기를 보존하는 용도가 아니다.
- 인식 정확도는 실제 PDF에 따라 다르며 미리보기에서 확인해야 한다. 자동 적용·자동 서버 저장은 하지 않는다.

## 작업 수명과 중복 호출

### 백그라운드 분석과 상태 표시

- Responses API에 `background: true`, `store: false`로 한 번 제출하고 응답 ID를 보관해 3초 간격으로 상태를 조회한다. 생성 POST는 자동 재시도하지 않는다. 상태 GET의 일시적인 네트워크 오류·429·5xx만 다시 조회한다.
- 우측 미리보기 영역에 로딩 원, 대기/분석/결과 확인 상태, 경과 시간, 마지막 OpenAI 상태 확인 시각, 분석 취소 버튼을 표시한다. 상태 확인 지연을 분석 실패나 가짜 진행률로 표현하지 않는다.
- 구조 분석과 음표 분석은 각각 최대 30분이다. 사용자가 마디 경계를 확인하는 시간은 포함하지 않는다. 30분 초과는 `ANALYSIS_TIMEOUT`으로 구분한다. 개별 요청 제한은 제출 90초, 상태 조회 20초다.
- 취소·시간 초과·서버 종료 시 알려진 응답 ID에 OpenAI 취소 요청을 보낸다. 외부 연결이 끊겨 취소 전달이 실패하면 원격 작업 중단은 보장할 수 없다. 최초 제출 응답을 받기 전에 연결이 끊겨 ID가 없는 경우에도 원격 취소는 보장할 수 없다.
- 백그라운드 처리에는 OpenAI의 임시 응답 보관이 사용된다. 모델은 백그라운드 처리를 지원해야 하며, 지원하지 않는 경우 자동으로 다른 모델이나 동기 요청으로 바꾸지 않는다.
- 작업과 응답 ID는 서버 메모리에 유지된다. 서버 재시작 후 진행 중인 작업의 자동 복원은 지원하지 않는다. DB 스키마 변경은 없다.

공식 동작: https://developers.openai.com/api/docs/guides/background

기존 모아잼 Bearer 인증을 사용하며 작업 소유자만 조회·재분석·삭제할 수 있다.
동일 사용자·동일 PDF는 유효한 작업을 재사용한다. 분석 중이거나 완료된 작업을 다시 시작해도 추가 호출하지 않는다.
사용자당 PDF 3개, 원본 전체 100MiB, 동시 분석은 사용자당 1개·전체 2개로 제한한다.
PDF와 결과는 서버 메모리에 최대 1시간 유지된다(분석 완료 시 만료 시간 갱신). 재시작 시 소실된다.
창을 닫았다 열면 같은 화면 인스턴스에서 진행 상황을 다시 조회한다. 화면 이동·브라우저 새로고침 후 자동 복구와 다중 서버 공유 저장은 아직 없다.
DB 스키마 변경과 마이그레이션은 없다. 코인 결제는 구현하지 않았다. 상용 결제 전에는 작업·사용량의 영속 저장과 차감/반환 처리가 필요하다.
API 키·PDF Base64·HTTP 오류 원문은 로그나 REST/MCP 결과에 포함하지 않는다. 기본 응답에는 변환 악보·경고·상태·사용량을 제공하며 성공·실패 모두 아래의 제한된 임시 진단을 추가한다.

### 임시 추출 진단

성공·실패한 작업의 `GET .../result`에 `diagnostics`를 추가한다. 작업 소유자만 조회할 수 있고 서버 메모리의 작업 수명(1시간)을 따른다.
최신 실패 1건의 단계, 모델, 요청/응답 ID, 중단 사유, 시도별 입력·출력·추론 토큰, 파트별 마디·이벤트 수와 GPT 경고를 확인한다.
모델 출력 JSON은 민감 필드를 가리고 최대 20,000자까지만 보관한다. 요청 본문, API 키, PDF Base64와 HTTP 오류 본문은 보관하거나 로그에 쓰지 않는다.
화면의 **추출 성공 진단 정보 (임시)** 또는 **실패 응답 진단 정보 (임시)**를 펼치거나 진단 JSON을 다운로드한다. 새 분석 시작 시 이전 진단은 초기화한다.
성공 진단은 민감 값을 제외한 전체 인식 JSON(`outputJson`, 최대 2,000,000자), 변환된 파트·보표 수, 마디별 박자 합계·쉼표·셋잇단·고스트 수와 변환 경고를 포함한다.
화면에서는 인식 JSON 앞 20,000자만 표시하며, 다운로드 파일에는 한도 내 전체 JSON을 담는다. 진단을 생성·다운로드해도 GPT를 다시 호출하지 않는다.
기능 추가 이전에 폐기된 실패 응답은 복구할 수 없다. 진단 조회 자체는 새 GPT 요청을 실행하지 않는다.

## REST

| 경로                                  | 기능                                                        |
| ------------------------------------- | ----------------------------------------------------------- |
| POST /v1/score-pdf/jobs               | multipart `file` 한 개, 업로드·검사·준비                    |
| POST /v1/score-pdf/jobs/:id/analyze   | 분석 시작. 실패한 작업의 명시적 재시도는 `{retry:true}`     |
| GET /v1/score-pdf/jobs/:id            | prepared / analyzing / completed / failed, 오류·누적 사용량 |
| GET /v1/score-pdf/jobs/:id/result     | 변환된 `result.score`와 `warnings`                          |
| POST /v1/score-pdf/jobs/:id/reanalyze | `{page, measure?}` 범위 재분석                              |
| DELETE /v1/score-pdf/jobs/:id         | 임시 PDF 제거·진행 중 요청 취소                             |
| GET /v1/assets/band-pdfs              | 가입한 밴드에서 접근 가능한 PDF 목록                        |

## MCP (stdio)

별도 MCP 프로세스가 위 REST 서비스를 호출한다. 웹은 MCP 없이 같은 서비스를 사용한다.

현재 분석은 구조 인식 후 `structure_review`에서 멈춘다. 사용자가 경계를 확인한 다음 추가된 `confirm_pdf_structure` 도구에 `{jobId, revision, structure}`를 전달하면 음표 분석을 시작한다(API 1회). `structure`와 `revision`은 결과 조회에서 받는다. 자동 확인은 하지 않는다. 기존 4개 도구에 이 확인 도구가 추가되어 총 5개다. 경계 좌표 및 웹 편집 방법은 [공통 인식 규칙](score-pdf-common-recognition.md)을 참고한다.

```json
{
  "command": "node",
  "args": ["C:/MoajamTest/Moajam/apps/server/scripts/score-pdf-mcp.mjs"],
  "env": {
    "MOAJAM_API_URL": "http://localhost:3000/v1",
    "MOAJAM_ACCESS_TOKEN": "모아잼 로그인 access token",
    "MOAJAM_PDF_DIRECTORY": "C:/MoajamTest/Moajam/data/pdf-input"
  }
}
```

PDF_DIRECTORY는 실제 존재하는 허용 폴더로 지정한다. 토큰은 OpenAI 키가 아니라 모아잼 로그인 토큰이며 만료 시 갱신한다.
`npm run mcp:score-pdf --workspace @moajam/server`로도 실행할 수 있다. stdout은 프로토콜 전용이다.

| 도구                    | 입력                      | 과금                  |
| ----------------------- | ------------------------- | --------------------- |
| start_pdf_analysis      | `{path: "PDF 절대 경로"}` | 새 분석 시 API 사용료 |
| get_pdf_analysis_status | `{jobId}`                 | 추가 GPT 호출 없음    |
| get_pdf_analysis_result | `{jobId}`                 | 추가 GPT 호출 없음    |
| reanalyze_pdf_section   | `{jobId,page,measure?}`   | 추가 API 사용료       |
